### BUG-3-001 — `next.config.ts` not supported in Next.js 14

| Field | Detail |
|---|---|
| **Status** | 🟢 RESOLVED |
| **Session** | Session 3 |
| **Severity** | High |
| **Module** | Setup |
| **Reported** | 2026-06-11 |

**Description:** Web dev server (T2) failed to start. `next.config.ts` is only supported in Next.js 15+. Next.js 14 accepts only `.js` or `.mjs` config files.

### BUG-3-003 — CI `--if-present` flag passed to tsc instead of pnpm

| Field | Detail |
|---|---|
| **Status** | 🟢 RESOLVED |
| **Session** | Session 3 |
| **Severity** | High |
| **Module** | Setup |
| **Reported** | 2026-06-11 |
| **Resolved** | 2026-06-11 |

**Description:** `pnpm run -r typecheck --if-present` forwarded `--if-present` as an argument to the underlying tsc call. tsc rejected it as an unknown flag, failing the CI typecheck job.

**Root Cause:** Flag position is significant in pnpm. The `--if-present` flag must appear before the script name: `pnpm -r run --if-present typecheck`.

**Fix Applied:** Corrected flag order.

**Files Changed:**
- `.github/workflows/ci.yml`

### BUG-3-009 — `db.execute()` binary protocol rejects LIMIT/OFFSET integer params

| Field | Detail |
|---|---|
| **Status** | 🟢 RESOLVED |
| **Session** | Session 3 |
| **Severity** | Critical |
| **Module** | CRM (all paginated endpoints) |
| **Reported** | 2026-06-11 |
| **Resolved** | 2026-06-11 |

**Description:** Every request to `/api/v1/contacts` (and any other paginated endpoint) returned HTTP 500 with `Error: Incorrect arguments to mysqld_stmt_execute`. The contacts list page was completely non-functional.

**Steps to Reproduce:**
1. Start API dev server
2. Browse to `http://localhost:3000/crm/contacts`
3. API logs show `Incorrect arguments to mysqld_stmt_execute` on every `GET /api/v1/contacts` request

**Root Cause:** mysql2's `execute()` uses the binary protocol (server-side prepared statements). In this protocol, JavaScript numbers are sent as DOUBLE (IEEE 754 float). MySQL's binary protocol rejects DOUBLE values for `LIMIT` and `OFFSET` clauses, which require `BIGINT UNSIGNED`. The `pageSize` and `offset` values from `paginationSchema` are valid JavaScript integers but arrive over the wire typed incorrectly.

**Fix Applied:** Changed the `query()` helper (used for all SELECTs) from `db.execute()` to `db.query()`. The text protocol escapes numeric params as integer literals, which MySQL accepts. The `execute()` helper (INSERT/UPDATE/DELETE) is unchanged — binary protocol is appropriate for write operations and LIMIT/OFFSET is not involved there.

**Files Changed:**
- `apps/api/src/db/query.ts`
